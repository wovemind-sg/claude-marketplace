# Features beyond the skeleton

Real projects started from `fastapi-template` grow things the Go skeleton has no file for. The inventory (`third_party_imports`, `grown_features`, `lifespan_steps`, `background_tasks`, `middlewares`) tells you which of these a project has. For each, this file gives the Go equivalent that fits the template's shape (one process, one binary, stdlib first) or says **ask** — meaning: do not pick for the user; put the question in the single AskUserQuestion of phase 3.

Rule of thumb when something is not listed: stdlib → a small well-known module → ask. Never add a framework.

Anything below that runs outside a request (workers, tickers, `BLPop` loops, an asynq server with its own Redis connection) is not covered by the server's `wakeDeps` middleware: create `w := wake.New("DB", pool.Ping)` (or `wake.New("REDIS", c.Ping)`) once and call `w.Wake(ctx)` before each job or tick (a client with its own connection, such as asynq, should ping through that client instead of `c.Ping`), so a Railway service that fell asleep is woken first.

| Feature (how it shows up) | Go equivalent / rule |
|---|---|
| **arq** background jobs — `from arq import create_pool`, `enqueue_job`, a `WorkerSettings` class, often an in-process `Worker` started in `lifespan` (so Railway runs one `web` process) | Jobs need retries, results or cron → `github.com/hibiken/asynq` (Redis-backed, same shape as arq: client enqueues, server runs handlers; start the server as a goroutine from `run()` bound to `ctx` so it stays one Railway process). Jobs are fire-and-forget with no retry → a goroutine pool consuming a Redis list via `BLPop`; or, if the queue only decouples latency, plain `go func()`. **Pickled arq jobs cannot be read by Go: drain the queue before cutover.** If jobs are long-lived or scheduled far ahead, **ask**. |
| **arq cron** / **APScheduler** / `asyncio.create_task(loop)` in lifespan | `time.Ticker` goroutine in `run()` that stops on `ctx.Done()`. More than one Railway replica → guard each run with `SET key NX EX` in Redis so only one replica does the work. |
| **OAuth login** (`authlib`, `starlette` OAuth client, Google / Apple sign-in; `state`/PKCE kept in signed cookies) | `golang.org/x/oauth2` + `golang.org/x/oauth2/google` for the code flow. Google ID-token verification → `google.golang.org/api/idtoken`. Apple: JWKS verification + ES256 client secret → `github.com/golang-jwt/jwt/v5` + `github.com/MicahParks/keyfunc/v3`. Keep the same cookie names for `state`/`code_verifier` so the flow's shape stays identical. Native (Capacitor) hop with hand-rolled signed cookie state: port as-is — it is just HMAC cookies. |
| **Push** — FCM via a service-account JWT (`PyJWT`), APNs, web push VAPID | `google.golang.org/api/option` + `oauth2/google.JWTConfigFromJSON` replaces hand-rolled JWT minting; web push → `github.com/SherClockHolmes/webpush-go`; APNs token auth → `golang-jwt/jwt/v5` ES256 (same key as Apple sign-in). |
| **Capacitor** wrapper (`mobile/` dir, `/.well-known/apple-app-site-association`, `assetlinks.json`, User-Agent sniffing, `X-Capacitor` headers) | `mobile/` is untouched (it is the web app in a shell). Port the `.well-known` routes with the exact `Content-Type` the Python route set (`application/json`, no extension). Header/UA checks are 1:1 on `r.Header`/`r.UserAgent()`. |
| **pytest unit tests** under `tests/` that import `app.` (not Playwright) | Decide per file in SPEC.md: tests of pure logic (money, dates, parsing, scoring, signing) → port to table-driven `_test.go` next to the Go code; tests of FastAPI glue (dependency wiring, route status codes) → delete, they are replaced by the handler tests and e2e suite. Never leave a Python unit test that imports `app.` — after cutover it cannot run. |
| **Email** (`smtplib`/`aiosmtplib`, `email.message`, `dnspython` MX lookups, reserved-domain guard) | `net/smtp.SendMail` (STARTTLS negotiated automatically with `smtp.PlainAuth`); multipart/alternative or attachments → `github.com/wneessen/go-mail`; MX check → `net.LookupMX`; HTML bodies via a separate `html/template` set (see `templates.md`). Keep the reserved-domain skip list. |
| **Stripe** webhooks | `Stripe-Signature` is `t=...,v1=hex(hmac_sha256(secret, t + "." + rawBody))` — ~15 lines of stdlib; read the body with `io.ReadAll` **before** JSON-decoding. Add `github.com/stripe/stripe-go` only if the app *calls* Stripe (checkout sessions, customers). |
| **RevenueCat** webhooks | compare the `Authorization` header with `hmac.Equal` and decode the JSON event — stdlib. |
| **Twilio** / other REST SDKs (`twilio`, `sendgrid`, `openai`, ...) | form-POST or JSON with `net/http` and basic auth; no SDK. Mirror `ai.send` for the error path. |
| **WebSockets** (`@app.websocket`) | **ask**: usually the feature is "push updates to the page" and HTMX's SSE extension on a `text/event-stream` handler covers it with less code. If true bidirectional is needed → `github.com/coder/websocket`. |
| **i18n** (`gettext`, Babel, a custom `t` filter + JSON catalogs, `Accept-Language` parsing) | **ask**: a JSON catalog per language + a `t` FuncMap closure chosen per request (cookie, then `Accept-Language`) is enough for most apps; `golang.org/x/text/message` only when plural rules or number formatting are needed. |
| **Pillow** (resize, thumbnails, EXIF rotate, format conversion) | stdlib `image`, `image/jpeg`, `image/png` + `golang.org/x/image/draw` (`draw.CatmullRom.Scale`); EXIF orientation → `github.com/rwcarlsen/goexif`; WebP *decode* → `golang.org/x/image/webp`; HEIC or WebP *encode* → **ask** (no pure-Go encoder; options are cgo `libvips`, an external service, or dropping the format). |
| **numpy / pandas / scipy / sklearn** | **hard ask** — there is no equivalent. Options: rewrite the algorithm in plain Go (fine for aggregations, scoring, simple stats), `gonum` for linear algebra, or keep a small Python sidecar service for that endpoint only. Do not start porting until the user picks. |
| **fastmcp** MCP server mounted on the app | tools/resources → `github.com/modelcontextprotocol/go-sdk` mounted at the same path. If the project also built an OAuth 2.1 authorization server for it (consent screens, token endpoint, Redis-backed codes) → **ask**; that is a session of its own. |
| **QR codes** (`qrcode`) | `github.com/skip2/go-qrcode` |
| **Markdown** rendering (`markdown`, `markdown-it`, `bleach`) | `github.com/yuin/goldmark` + `github.com/microcosm-cc/bluemonday` returning `template.HTML` |
| **Timezones** (`pytz`, `dateutil`, `zoneinfo`) | `time.LoadLocation` plus `import _ "time/tzdata"` in `main.go` — the Railway image is minimal and the binary is static, so without it `LoadLocation` fails in prod and works on your laptop |
| **Rate limiting** (`slowapi`, hand-rolled Redis counters) | keep the hand-rolled Redis `INCR`/`EXPIRE` with the same keys; `golang.org/x/time/rate` only for in-memory limits that don't need to be shared across replicas |
| **CSRF** tokens (hand-rolled, signed cookie + hidden field) | same signed-cookie helper; `hmac.Equal` on compare |
| **Turnstile / reCAPTCHA / analytics keys** exposed to templates as globals | `view()` globals (see `templates.md` (c)); the verify call is a `net/http` POST |
| **File storage** (S3 / R2 via `boto3`, local uploads dir) | `github.com/aws/aws-sdk-go-v2` (S3-compatible endpoints incl. R2); local dir → `os.WriteFile` + `http.FileServer(http.Dir)` |
| **Sentry / OpenTelemetry** | `github.com/getsentry/sentry-go` with the `http` middleware; OTel → `go.opentelemetry.io/otel` + `otelhttp` |
| **GitHub Actions** running `uv sync`, `alembic upgrade`, `pytest` | rewrite to `go build ./... && go vet ./... && go test ./...`, `./out migrate up` against the CI DB, then `uv run pytest tests/...` with the Go server started (see `cutover.md`) |

## What "ask" means in practice

Collect every **ask** item from the inventory into the one AskUserQuestion of phase 3, each with the options above as choices and the recommended one first. Record the answers in `.planning/SPEC.md` next to the session that implements them. Do not re-ask inside the implementing sessions.
